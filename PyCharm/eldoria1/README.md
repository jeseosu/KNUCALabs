# Echoes of Eldoria

Текстова **MMORPG для одного гравця** в ASCII-стилі, написана на Python 3 з бібліотекою `curses`.
Відкритий світ 240×120 з чотирма біомами, місто, вісім підземель з босами, квести, торгівля, крафт,
аукціон з ботами-«гравцями», світові події, туман війни та збереження прогресу.

Лише стандартна бібліотека, жодних залежностей. Потрібен **Python 3.10+** (розроблено на 3.14, macOS).

## Запуск

```bash
cd eldoria
python3 main.py
```

Запускати треба в Terminal.app, iTerm або іншому справжньому терміналі (не у вбудованому терміналі IDE).
Розмір вікна: щонайменше **80×32**.

Тести:

```bash
python3 -m unittest tests.test_save_load -v
```

Перед здачею в `game/config.py` постав `DEBUG = False`, щоб вимкнути чит-клавіші.

## Структура проєкту

```
eldoria/
├── main.py                 # точка входу: меню -> гра -> меню
├── data/                   # увесь контент у JSON (баланс, предмети, квести...)
├── saves/                  # збереження гравця
├── tests/                  # автотести (unittest)
└── game/
    ├── config.py           # константи та клавіші
    ├── engine.py           # головний цикл, ввід, хід гри
    ├── state.py            # GameState: усе, що зберігається
    ├── entities/           # Entity -> Player, Monster, NPC
    ├── items/              # Item, Inventory, лут
    ├── systems/            # бій, квести, діалоги, крафт, ринок, події
    ├── world/              # тайли, генератор світу, підземелля, зони
    ├── ui/                 # відмальовка (curses), меню, екрани
    └── persistence/        # збереження та завантаження
```

## Архітектурні рішення

- **Data-driven дизайн.** Монстри, предмети, квести, рецепти, події, підземелля та крамниці описані
  в JSON. Додати новий квест чи монстра можна без змін у Python.
- **Розділення шарів.** Логіка (`systems/`, `entities/`, `state.py`) не знає про `curses`.
  Відмальовка (`ui/`) тільки читає стан. Діалог лише ставить `pending_menu`, а рушій відкриває екран.
- **ООП та поліморфізм.** `Player`, `Monster`, `NPC` успадковують `Entity`. Властивості `power` і `armor`
  перевизначені в `Player` з урахуванням спорядження, тож бойова система не знає, хто б'ється.
- **Подієва модель.** Бій повідомляє про вбивство квестам (`on_kill`) і світовим подіям (`events.on_kill`),
  а ті реагують незалежно.
- **Ефекти світових подій.** Кожна подія описує словник `effects`, а код у різних місцях питає
  `events.mult("ключ")`. Нова подія додається лише в `world_events.json`.

## Алгоритми

- **Алгоритм Брезенхема** для ліній польоту снарядів і перевірки видимості в тумані війни.
- **Біоми:** сектори навколо міста через `atan2`, межі викривлені синусами (органічний вигляд без шуму Перліна).
- **Підземелля:** розміщення кімнат без перетину, з'єднання кожної нової кімнати з найближчою
  (гарантує зв'язність), L-подібні коридори, бос у найдальшій кімнаті.
- **Зростання монстрів:** `min(8, int(sqrt(хід / 150)))`, швидкий старт і повільне насичення.
  Підсилення ледаче: монстр підсилюється, коли його вперше побачили.
- **Ринок аукціону:** попит повертається до середнього (`d += (1 - d) * 0.12 + шум`), а ймовірність
  купівлі лота ботом падає зі зростанням ціни (`0.9 - 0.6 * ціна / справедлива_ціна`).
- **ШІ монстрів:** скінченний автомат із жадібним пошуком шляху й обходом перешкод.
  Монстри далі 36 клітинок «сплять», тому великий світ не гальмує.

## Збереження

Файли `saves/slot1.json` ... `slot3.json` і `saves/autosave.json`. Зберігається повний стан:
гравець, усі карти (поверхня та відвідані підземелля), монстри, NPC, здобич, відкрита територія,
квести, ринок, світова подія, прогрес підземель і навіть стан генератора випадкових чисел
(після завантаження гра продовжується детерміновано).

- Файл пишеться у тимчасовий, потім підміняється через `os.replace`: збереження не псується при збої.
- Формат має версію (`SAVE_VERSION`); несумісні або пошкоджені файли відхиляються з поясненням.
- Відкрита територія кодується рядками з `0` і `1` замість списку пар координат.
